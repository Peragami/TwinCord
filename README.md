# TwinCord

[![CI](https://github.com/Peragami/TwinCord/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Peragami/TwinCord/actions/workflows/ci.yml)
[![Latest release](https://img.shields.io/github/v/release/Peragami/TwinCord?label=release)](https://github.com/Peragami/TwinCord/releases/latest)
[![Platform](https://img.shields.io/badge/platform-Windows%2010%202004%2B-0078D4?logo=windows&logoColor=white)](#必要環境)

2アカウント同時常駐の軽量Discordラッパー (Windows / C# + WebView2)

公式デスクトップ版を2つ起動すると重いため、OS共有のWebView2ランタイム上に
Discord公式Web版を2枚埋め込み、1プロセスで2アカウントを同時利用します。

## 機能

- Discord風の左レールで2アカウントを切替(両方常駐、通知ソケット維持)
- レールにDiscordアバター表示、ダブルクリック/右クリックで改名
- 非表示側の未読バッジ、メンション等のバルーン通知(クリックで該当アカへ移動)
- 通知タブで通知を集中制御(全体ON/OFF・表示中スキップ・格納中のみ)
- 通知履歴(トレイメニューから表示)
- トレイ常駐、二重起動時は先発ウィンドウを表示
- ページ内 `Ctrl+1/2` でアカウント切替、グローバル `Ctrl+Alt+1/2/M` でも可
- アカ別ミュート(状態は保存)、拡大率(50〜200%)、Windows自動開始、起動時最小化
- 起動時の更新自動確認とワンクリック更新(GitHub Releases連携)
- サーバーリストのダウンロードボタン隠し(設定変更はすぐ反映)、リンクホバーURL表示の抑制
- Discord風のダークUI(設定・履歴・更新ダイアログ)
- 通話中はメモリ抑制・自動リロードを回避(プロセス異常時の復旧を除く)
- 起動時は表示中のアカウントを先に読み込み、2枚目は1枚目の表示完了後に初期化(初回表示を優先)
- 自己診断(応答速度・メモリ・バッジ・アバター状態)と劣化通知
- 設定のエクスポート/インポート(インポートは「保存」で確定)
- 省メモリ: 非表示側/トレイ格納中のヒープ抑制、最小化時のワーキングセット返却、手動再読み込み
- 省CPU: バッジ・未読・通話の確認は1回のスクリプト実行にまとめ、変化が無いときは確認間隔を自動で延長
- 省メモリ(共有): 2アカウントでブラウザ/GPUプロセスを共有し、ログインだけをプロファイルで分離
- 省メモリ(起動時): アプリ本体を単一exeに詰め込まずファイルとして配置する構成のため、起動直後のホストメモリは90MB前後(プロセス全体は自己診断で確認可)
- ポータブル: 設定・ログイン情報・履歴はアプリのフォルダ内(`data`)に保存。フォルダを消せば完全に削除できる

## 必要環境

- Windows 10 (2004 / ビルド19041) 以降 / Windows 11 (WebView2 ランタイム標準搭載)
- .NET 10 SDK (ビルド時)
- .NET 10 ランタイム … 開発用の軽量版(`scripts\publish.bat`)を動かすときだけ必要。
  リリース版はランタイム同梱なので不要

## 入手

[Releases](https://github.com/Peragami/TwinCord/releases) から `TwinCord.zip` をダウンロードし、
**書き込みできる場所**(デスクトップやドキュメントなど)へ「すべて展開」してから、
出てきた `TwinCord.exe` を実行してください。ランタイム同梱なので **.NET のインストールは不要**です。
アプリ内の自動更新にも対応しています。

- 初回起動時にWindowsのセキュリティ警告(SmartScreen)が出ることがあります。「詳細情報」→「実行」で
  許可してください。ダウンロードしたzipを右クリック→プロパティ→「ブロックの解除」を先に行うと、
  展開後のファイルで警告が出にくくなります。
- Program Filesなど書き込みできない場所へ置くと起動できません(データを隣に保存するため)。
- `TwinCord.exe` の名前は変えないでください(自動更新がこの名前を使います)。

## データの保存場所と削除(ポータブル形式)

設定・通知履歴・ログ・アバター・Discordのログイン情報は **アプリのフォルダ内の `data\`** に保存します
(%LOCALAPPDATA%など外の場所は使いません)。アンインストールは次の3手順だけです。

1. 設定で「Windows起動時に自動開始」をオフにする(オンにしていた場合)
2. TwinCordを終了して数秒待つ(WebView2の子プロセスが残っていると削除に失敗します)
3. アプリのフォルダを丸ごと削除する

`data\webview2\` はログイン情報とキャッシュでサイズが大きくなりますが、フォルダごと消せば残りません。
旧バージョン(1.10.xまで)のデータが `%LOCALAPPDATA%\TwinCord` にある場合は、
初回起動時に引き継ぎの確認が出ます(「いいえ」を選ぶと新規状態で始まります)。

## 配布物作成

```bat
scripts\publish-portable.bat        :: リリース用。フォルダ構成と TwinCord.zip (ランタイム同梱・約72MB)
scripts\publish.bat                 :: 開発用の軽量版。フレームワーク依存 (.NET 10 が必要)
```

配布のルール:

- **リリースには `publish-portable.bat` が作る `TwinCord.zip` をその名前で添付**します。
  アプリの自動更新は `TwinCord.zip` という名前の添付を探すため、この名前が必須です。
- 更新はzipをダウンロードしてSHA256で検証し、アプリのフォルダへミラー同期します
  (`data` と `mods` は対象外なので設定・ログイン情報・modは残ります)。SHA256が取得できない
  場合は自動更新を中止します。同期前にアプリ本体を退避し、失敗時は元のファイルへ戻して再起動します。
  更新に失敗した場合は理由を `update-error.log` に残し、次回起動時に通知します。
  そのため **アプリのフォルダに私物のファイルを置かないでください**(更新で消えます)。追加物は `data\` か `mods\` へ。
- 単一exe配布は廃止しました(`scripts\publish-selfcontained.bat` は必要になったときの例外用)。
  単一exeで起動している場合は自動更新できないため、手動でzip版へ移行してください。
- `publish.bat` の成果物は開発中の手軽な起動用で、リリースには添付しません。
- スクリプトは失敗時は終了コード1を返し、古い成果物を残したまま成功扱いにはしません。

## メモリの共有(2アカウント)

2アカウントで1つのWebView2環境(ブラウザ/GPU/ネットワークのプロセス)を共有し、
ログイン情報だけをプロファイルで分けています。ブラウザ系プロセスが1組で済むため、
アカウントごとに環境を持つ方式よりメモリとプロセス数が少なくなります(実測: 15→9プロセス)。

- ログインは独立したまま、通知も両方に届きます(非表示側のメモリ抑制もそのまま動きます)。
- 旧方式のデータ(`acc1` / `acc2` フォルダ)は使用しません。削除しても構いません。
- ブラウザプロセスを共有するため、ブラウザプロセス自体が終了すると両方操作できなくなります。
  その場合は再起動を促すメッセージを表示します(ページ単位のクラッシュは片方だけ再読み込みします)。

## 注意(アカウント安全性について)

コード全体を確認した上での整理です。

- 表示しているのはDiscord公式Web版そのもので、トークンの抜き出しや
  非公開APIの直接利用、メッセージの自動送信・自動操作機能はありません。
  外部通信はDiscord本体・Discord CDN(アバター画像)・GitHub(更新確認と更新ファイルの取得)です。
  更新ファイルはGitHubの当該リポジトリからのみ取得し、SHA256を必須で検証してから入れ替えます。
  SHA256が取得できない場合は自動更新を行いません。
- ページ側に行っているのは受動的な処理のみです: 通知の受け取り、
  未読バッジ等の読み取り、キー操作の検出、ダウンロードボタンの非表示化。
- ブラウザの正体は通常のEdge(WebView2)として見えるため、一般的な
  広告ブロッカー等と同程度の見え方です。BANの検出対象になるような
  自動化・マクロ・スパム行為は搭載も想定もしていません。
- とはいえ100%の安全保証はできません。規約上は公式クライアントの利用が
  前提のため、利用は自己責任でお願いします。特に自動化ツールや
  マクロとの併用は避けてください。
- Discord側の更新で一部機能(未読バッジ等)が動かなくなる場合があります。
  その際は設定→アプリについて→自己診断で確認してください。

## バージョニング方針(厳密SemVer)

- パッチ(x.y.Z): 不具合修正・内部改善・文言変更。動作仕様は不変
- マイナー(x.Y.0): 機能追加(後方互換あり)
- メジャー(X.0.0): 破壊的変更(設定形式の非互換変更等)のみ

公開済みの番号は下げません。2.0は破壊的変更があるときだけです。

履歴の記載元はこのREADMEのみです(アプリ内の「変更履歴」は下の節をそのまま読み込んで表示します)。
