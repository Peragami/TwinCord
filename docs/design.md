# 設計メモ

## WebView2 環境の共有

2アカウントで1つの WebView2 環境(ブラウザ/GPU/ネットワークのプロセス)を共有し、ログイン情報だけをプロファイルで分けています。アカウントごとに環境を持つ方式より、メモリとプロセス数が少なくなります(実測: 15→9プロセス)。

- ログインは独立したまま、通知も両方に届きます。
- ブラウザプロセス自体が終了すると両方を操作できなくなるため、再起動を促します。
- ページ単位のクラッシュは片方だけ再読み込みします。
- 旧方式のデータ(`acc1` / `acc2` フォルダ)は使用しません。

## 起動シーケンス

- 表示中のアカウントを先に読み込み、2枚目は1枚目の表示完了後に初期化します。
- 初回読み込み前のメモリ抑制は行いません(描画開始の遅れを防ぐため)。
- 起動時間の計測ログを記録します。

## メモリ

- 非表示側・トレイ格納中はヒープを抑制します。
- 最小化時にワーキングセットを返却します。
- 通話中はメモリ抑制と自動リロードを回避します(プロセス異常時の復旧を除く)。
- 手動の再読み込みで状態を戻せます。

## CPU

- バッジ・未読・通話の確認を1回のスクリプト実行にまとめています。
- 変化がないときは確認間隔を自動で延長します。

## 監視と復旧

- 自己診断で応答速度・メモリ・バッジ・アバター状態を確認します。
- 動作の劣化を検知すると通知します。
- WebView2 ブラウザプロセスの終了時は通知し、レンダラ異常時は再読み込みします。

## 主要な構成

- `Core/` … 設定、更新、診断、ログ、変更履歴
- `Services/` … ページ監視、スクリプト、更新処理、アバター
- `Views/` … メインウィンドウ(役割別 partial)、設定、履歴、更新ダイアログ
- `TwinCord.Tests/` … 単体テスト
